================================================================================
                            DATASET OVERVIEW
================================================================================

SOURCE: Company internal maintenance records

DIMENSIONS:
  * Total rows: 1,048,575 (Excel row limit)
  * Valid records: 93,318 (with both Description and Text)
  * Cleaned records: 40,000+
  * Columns: 3 (WO No., Description, Text)
  * File size: 16 MB

FEATURES:
  WO No.       : Work Order identifier (numeric)
  Description  : Problem summary (free text, ~10-50 words)
  Text         : Technician notes with solution (free text, ~20-100 words)

DATA QUALITY:
  * Encoding: ISO-8859-1 (legacy)
  * Errors: #N/A placeholders, invalid WO numbers, empty fields
  * Contamination: Technician names (BRAD, CHAD, FOX) mixed with solutions
  * Inconsistency: Mixed case, variable punctuation

SAMPLE:
  WO #20033463 -> Description: "CONVEYOR NOT WORKING"
               -> Text: "TURNED CURRENT UP ON DRIVE & PUT BELT TIGHTENED..."

================================================================================
                         ML ARCHITECTURE OVERVIEW
================================================================================

STAGE 1: DATA PREPROCESSING
  Input:  Raw CSV (1M rows)
  Process: Clean, validate, lowercase, remove punctuation
  Output: 40K clean records with Description_cleaned, Text_cleaned columns

STAGE 2: UNSUPERVISED CLUSTERING
  Algorithm: KMeans (k=5 clusters)
  Input:    Text_cleaned (technician notes)
  Features: TF-IDF vectorization (5000 max features, English stop words)
  Output:   Note_Cluster (0-4) for each record
  
  Cluster Distribution (Severe Imbalance):
    Cluster 0: 8,250 (73%)  - Adjustment/Cleaning actions
    Cluster 1: 2,096 (19%)  - Component Replacement
    Cluster 2:   282 (2.5%) - Simple Completion
    Cluster 3:   287 (2.5%) - Repair Broken Items
    Cluster 4:   388 (3.4%) - Electrical/Wiring Repair

STAGE 3: SUPERVISED CLASSIFICATION
  Algorithm: Logistic Regression (max_iter=1000)
  Input:     Description_cleaned (work order descriptions)
  Target:    Note_Cluster (from Stage 2)
  Features:  TF-IDF vectorization
  Split:     80% train, 20% test
  
  Performance by Cluster:
  ┌─────┬──────────┬────────┬────────┬──────────────┐
  │ ID  │ Accuracy │ Recall │ F1     │ Interpretation│
  ├─────┼──────────┼────────┼────────┼──────────────┤
  │  0  │   0.96   │  0.85  │ 0.76   │ Good         │
  │  1  │   0.19   │  0.27  │ 0.47   │ Poor         │
  │  2  │   0.01   │  0.02  │ 1.00   │ Very Poor    │
  │  3  │   0.05   │  0.09  │ 0.38   │ Very Poor    │
  │  4  │   0.03   │  0.06  │ 0.27   │ Very Poor    │
  └─────┴──────────┴────────┴────────┴──────────────┘

STAGE 4: INFERENCE & SIMILARITY SEARCH
  Function: get_predictions(description_input, pipeline, df, top_n=5)
  
  Process:
    1. Predict most likely technician action cluster
    2. Filter database to that cluster (~8K records for Cluster 0)
    3. TF-IDF vectorize input description
    4. Compute cosine similarity to all cluster descriptions
    5. Return top N most similar historical work orders
  
  Output: Recommended solutions with WO numbers and technician notes
